= nav-typology
:description: Antora extension for uniform SVG typology icons in sidebar navigation.
:page-audience: Antora hub maintainers
:page-usage-context: Register after site-nav-tree; optional nav-typology-diataxis plugin for Diátaxis sites

Structural navigation labels (Diátaxis buckets, component roots, spec groupings) should look identical on every OS. Unicode emoji in nav titles vary by platform font and steal design space from expressive emoji elsewhere.

*nav-typology* enriches Antora navigation items at build time with `navTypology` metadata and renders a shared SVG sprite in the sidebar via an overridden `nav-tree` partial.

== Install

[source,bash]
----
pnpm add -D github:antora-supplemental/nav-typology#main
----

Optional Diátaxis auto-detection (separate package — not in default Facto hard deps):

[source,bash]
----
pnpm add -D github:antora-supplemental/nav-typology-diataxis#main
----

== Playbook

Register **after** `@antora-supplemental/site-nav-tree` so component forest roots receive typology icons.

[source,yaml]
----
antora:
  extensions:
    - require: '@antora-supplemental/site-nav-tree'
      include: [home, general-knowledge]
    - require: '@antora-supplemental/nav-typology'
    - require: '@antora-supplemental/nav-typology-diataxis'
----

== Behavior

* Wraps `NavigationCatalog#getNavigation` after Antora builds nav (same hook pattern as site-nav-tree).
* **Component-root icons are off by default** (opt in: `site.keys.nav_typology_component_root_icons: 'true'`). Typed leaves/sections keep solid SVG glyphs.
* Detects typologies from URL paths, unlinked bucket titles, parent inheritance, and depth (component forest roots at depth 0; changelog / activity-log).
* Explicit override: set `navTypologyId` on a nav item object (extension API; Antora nav.adoc attribute wiring is future work).
* Hoists changelog siblings to position 2 in each nav branch (after the first landing link).
* Strips leading structural emoji from nav labels when a typology icon replaces them.
* Injects companion UI at build time (`uiLoaded`): `nav-tree` partial, helpers, CSS, and SVG sprite. Stylesheet link is appended to `head-meta` when present.

== Companion UI

**Default:** no manual copy step. On `uiLoaded`, the extension merges `ui/` into the Antora UI catalog and replaces any stale files under hub `supplemental-ui/` with the same paths.

Optional hub-only overrides: copy files into `supplemental-ui/` *after* disabling injection (`ui: false` on the extension require) or fork individual partials/helpers locally.

Legacy manual copy (pre v0.1.12) is obsolete once the playbook pins `@antora-supplemental/nav-typology` >= `v0.1.12`.

== Explicit typology (page attrs)

Prefer **explicit** typology over inventing URL-folder heuristics when the path is tree hierarchy (Business Bootstrap capability areas). Set on the page:

[source,asciidoc]
----
= Escalate DMARC policy
:page-nav-typology: diataxis-howto
----

Or pass `navTypologyId` on a nav item from another extension. Antora `nav.adoc` attribute wiring remains optional future work.

== Optional config

[source,yaml]
----
- require: '@antora-supplemental/nav-typology'
  stripEmoji: true
  componentTypologies:
    DevCentr: component-root
    general-knowledge: component-root
  # Skip Diataxis URL path markers under these prefixes (tree = hierarchy).
  diataxisUrlExcludePrefixes:
    - /business-bootstrap/
----

== Plugins

`@antora-supplemental/nav-typology-diataxis` enables the `diataxis` plugin (path/title rules for tutorial / how-to / reference / explanation). Sites that do not use Diátaxis omit that package entirely.

**Ship v1:** register the extension + copy companion UI into `supplemental-ui/` and link `nav-typology.css` in `head-meta.hbs` (see site-nav-tree / site-math pattern). Optional `nav-typology-diataxis` for Diátaxis sites only.

== Demo data

Typology icons apply to nav items from whatever `content.sources` you compose — there is no separate `nav-typology` fixture component.

* Multi-root forest smoke: compose link:https://github.com/antora-supplemental/demo-data[`demo-data`^] `docs/fixtures/site-nav-tree` and register site-nav-tree + nav-typology (see site-nav-tree README).
* Baseline body pages: `demo-data` `docs/demo-pages` — do not duplicate in this repo.
* Pattern: link:https://docs.antora-supplemental.org/docs/ROOT/proposals/demo-data-catalog.html[Demo data catalog^].
